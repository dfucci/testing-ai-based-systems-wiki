Summary: “Boundary tracing”: observe an agent from outside its code at two stable interfaces — decrypted LLM traffic (intent) and kernel events (actions) — using eBPF, correlate the two streams by process lineage, time and argument matching, then have a secondary LLM analyze the trace. Overhead averages 2.9% on three developer workflows; detection is shown in three single-instance case studies (indirect prompt injection, a reasoning loop, multi-agent coordination), without detection rates.

Problem: the semantic gap

An agent couples an LLM with tools that spawn processes, edit files and run commands, so its intent is expressed in natural language and its actions are generated at runtime. Existing observability sits on one side of that gap: (source: Zheng et al. 2025)

  • Intent-side tools (LangChain/AutoGen instrumentation; Langfuse, LangSmith, Datadog; OpenTelemetry GenAI conventions under the “AgentOps” label) trace prompts and tool selection but are blind to out-of-process actions — a single shell command escapes them.
  • Action-side tools (Falco, Tracee) see every syscall but lack the semantics to tell a benign script from a malicious one.

The paper’s example: an agent that reads a malicious instruction from an external URL during a documentation search and injects a backdoor looks, to an application monitor, like a successful “execute script” call, and to a system monitor like a bash process writing a file. Neither links the two.

Approach

Boundary tracing: all interactions pass through the kernel and the network, and those interfaces (syscall ABIs, network protocols) change far more slowly than agent frameworks. Monitoring there is framework-agnostic, needs no instrumentation and does not rely on a cooperative agent. (source: Zheng et al. 2025)

  • Intent stream: eBPF uprobes on SSL_read / SSL_write in crypto libraries such as OpenSSL capture decrypted LLM requests and responses; a userspace daemon reassembles streaming (Server-Sent Events) responses.
  • Action stream: tracepoints such as sched_process_exec build a process tree; kprobes watch syscalls such as openat2, connect, execve. An in-kernel filter tracks fork/execve lineage so only events from the agent and its descendants reach userspace, avoiding brittle static filters (a rule for git fails when the agent uses curl and bash instead).
  • Stage-1 correlation engine (Rust userspace daemon, ~6,000 lines Rust/C plus ~3,000 lines TypeScript frontend): links an LLM response to the system behavior it triggers with three signals — process lineage, temporal proximity (a 100–500 ms window after an LLM response) and argument matching (filenames, URLs, commands in the response versus later syscall arguments). It also enriches events (e.g. file descriptor → path).
  • Stage-2 semantic analysis: the correlated trace is formatted and sent to a secondary “observer” LLM prompted as a security analyst; its natural-language analysis and confidence score are the output. Processing is asynchronous to contain latency and cost.

Evaluation

Overhead

Ubuntu 22.04, Linux 6.14.0, Claude Code 1.0.62 with Claude 4; three workflows, three runs each with and without AgentSight (source: Zheng et al. 2025):

Workflow Baseline (s) With AgentSight (s) Overhead
Understand repo (/init) 127.98 132.33 3.4%
Code writing (bpftrace scripts) 22.54 23.64 4.9%
Repo compilation (parallel build) 92.40 92.72 0.4%

Average overhead reported: 2.9%.

Case studies (one instance each)

  • Indirect prompt injection: an agent told to clone and build a C project follows a README link to a page with a hidden prompt, then reads and sends /etc/passwd to a collection server in a command disguised as a build step. AgentSight captured the chain from URL fetch to exfiltration — 521 raw events merged into 37 by the correlation engine — and the observer LLM returned a high-confidence attack score, concluding the actions were logically inconsistent with the stated goal.
  • Reasoning loop: a research agent built with crewAI and gpt-4o-mini repeatedly called a web-search tool with incorrect arguments, got an error and retried the same failing call. Real-time monitors flagged the anomalous API consumption; the observer LLM named the cause as a persistent tool error and a “try-fail-re-reason” loop in which the agent did not learn from the tool’s output.
  • Multi-agent coordination: six collaborating Claude Code subagents working on the authors’ repository produced 3,153 events after correlation. Frontend and test agents were sometimes blocked by sequential dependencies and retry cycles from file-lock contention; the analysis suggested separating roles more clearly to reduce runtime and token cost.

Scope of the evidence

Each case study is a single instance. The paper reports no detection or false-positive rates and no comparison against intent-only or action-only tools, and the observer LLM’s verdicts are not independently validated in the paper. Interception probes SSL_read / SSL_write in crypto libraries such as OpenSSL. The paper names the latency and cost of LLM analysis as a challenge, mitigated with asynchronous processing and prompt engineering. AgentSight observes and reports; it does not block actions. (source: Zheng et al. 2025)

Relation to the rest of the wiki

Tangent’s interviewees say they rely on post-deployment observability (OpenTelemetry, LangSmith, Langfuse, Arize AI) instead of formal test suites (see LLM Agent Testing Practice); AgentSight names Langfuse, LangSmith, Datadog and the OpenTelemetry GenAI conventions as intent-side observability and says such tools cannot see out-of-process actions. (source: Pan et al. 2026; Zheng et al. 2025) For comparison, TRAJEVAL compares trajectories against a reference patch (Trajectory Analysis), and AgentSpec intercepts and blocks actions at runtime (Runtime Enforcement). Indirect prompt injection is also discussed in Agent Safety.
