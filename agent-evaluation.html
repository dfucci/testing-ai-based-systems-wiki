Outcome-Based Metrics

Pass@k

Probability of generating a correct solution within k attempts. Standard metric for code agents on SWE-bench. Collapses entire execution into a binary signal — passes or fails. Cannot reveal where or why an agent failed.

(source: Chen, 2021, cited in TRAJEVAL)

CodeBLEU

Measures syntactic and semantic similarity of generated code to reference. Operates on outputs, not process. Does not capture whether agent explored the right code regions.

Efficiency metrics

Token consumption, latency, cost per solution. Measure operational costs but not behavioral quality.

Process-Based Metrics (TRAJEVAL)

TRAJEVAL introduces stage-wise precision and recall metrics that measure how agents arrive at solutions:

Metric What it measures
Search P/R File localization accuracy/coverage
Read P/R Function comprehension accuracy/coverage
Edit P/R Modification targeting accuracy/coverage

Key finding: these 6 features predict model-level Pass@1 within 0.87–2.1% MAE, demonstrating that process metrics carry strong predictive signal. (source: TRAJEVAL paper)

Safety-Oriented Evaluation

For agent safety, evaluation focuses on whether agents execute harmful actions. Key benchmarks:

  • RedCode-Exec: 750 risky code scenarios across 25 vulnerability categories (source: AgentSpec paper)
  • SafeAgentBench: embodied agent safety, 250 scenarios across 10 hazard categories
  • FixDrive: autonomous vehicle law-violation scenarios

Safety evaluation uses enforcement rate (fraction of risky actions successfully blocked) and false positive rate (safe actions incorrectly blocked).

Generalization Evaluation

TRAJEVAL identifies three increasingly challenging distribution shifts:

  1. Instance-held-out: random 60/40 split (in-distribution)
  2. Repository-held-out: train on 60% of repos, test on unseen ones (cross-codebase)
  3. Language-held-out: train on Python/JS, test on TypeScript/Java (cross-language)

Results: for the SWE-Agent/SWE-bench configuration specifically, trajectory features maintain perfect ranking correlation (ρ=1.00) under both repo-held-out shift (MAE 1.20%→2.73%) and language-held-out shift on PolyBench (MAE up to 8.83%) — ranking correlation stays perfect even as absolute MAE degrades. Across all agent/benchmark configurations tested, the reported floor is ρ≥0.886 (some configs, e.g. PolyBench repo-held-out, dip to ρ=0.94), so “perfect” ranking preservation is the common case, not a universal guarantee. (source: Kim et al. 2026)

Limitations of Current Evaluation

  • Binary outcomes hide failure structure: models with same Pass@1 may fail in completely different ways
  • Reference-patch assumption: trajectory metrics assume reference patches represent canonical solutions (TRAJEVAL validates this: 93.3% of multi-solved instances show exact function-level convergence)
  • Architecture dependence: agent architectures with different tool primitives make cross-agent comparison complex
  • Safety vs. capability trade-off: safety benchmarks measure constraint enforcement, not whether safe alternatives were found

Evaluation Without Ground Truth

For agent outputs with no fixed correct answer, REAG proposes requirements-grounded oracle generation plus a confidence-calibrated LLM-as-judge cascade (conformal risk control, abstention on low confidence) as an alternative to fixed benchmarks. Empirically, Tangent finds most real-world agent test suites still rely on shallow unit assertions rather than this kind of behavior-level evaluation — see LLM Agent Testing Practice.

Formal and Adequacy-Based Alternatives to Benchmark Scores

Lean4Agent shows that a design-time formal-verification pass on the workflow specification itself is predictive of downstream benchmark performance (11.94% average gain for verification-passing workflows) — an evaluation signal available before running any benchmark task. See Formal Verification of Agent Workflows.

Separately, Skill Coverage evaluates agent skill documents rather than task outcomes: it shows that passing a benchmark task and thoroughly exercising the skill guidance behind it are different things — SkillsBench executions cover only 39.90-43.98% of documented skill behavior despite high task pass rates. See Agent Skill Coverage.
