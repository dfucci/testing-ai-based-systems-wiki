Summary: Instead of mutating source syntax, this approach uses an LLM to mutate the natural-language programming intent behind a function and then re-implements that mutated intent as code — producing mutants that are semantically diverse and 55% not subsumed by traditional syntax-based mutants.

Sources:

  • Hamidi et al. - 2025 - Intent-Based Mutation Testing From Naturally Written Programming Intents to Mutants.pdf

Last updated: 2026-10-18

Motivation

Traditional mutation testing changes how a program is written (flip an operator, negate a condition), which is effective for surface-level faults but stays confined to the logic actually implemented — it can’t easily represent faults that arise from a programmer’s misunderstanding of the specification (omission faults, corner cases outside what was implemented). (source: Hamidi et al. 2025)

Approach

Define an “intent” as the programmer’s natural-language objective for a function (e.g. “a function that computes the factorial of an integer”). Intent-based mutation testing uses an LLM to (1) extract the intent implemented by the program under test, (2) generate mutated variants of that intent representing plausible misunderstandings or corner-case variations, and (3) implement each mutated intent as a new candidate program (the mutant). Because the mutant is generated from a different specification, not a syntactic edit, it can diverge from the original in ways syntax-based mutation structurally cannot reach. (source: Hamidi et al. 2025)

Findings

Evaluated on 29 programs: intent-based mutants are syntactically more complex, semantically more diverse, and meaningfully different from traditional (syntax-based) mutants — 55% of intent-based mutants are not subsumed by any traditional mutant, meaning a test suite that kills all traditional mutants can still miss these. The authors position intent-based mutation as a complement to, not a replacement for, traditional mutation testing. (source: Hamidi et al. 2025)

Relation to broader wiki

This is a direct instance of using an LLM’s ability to interpret and reformulate natural-language specifications to attack the classic mutation-testing “coupling effect” assumption — that small syntactic changes stand in for all real faults. It pairs naturally with MuMuTestUp, which uses (traditional) mutation testing as a signal to strengthen test assertions in the LLM era; see Mutation Testing for LLM Systems for the synthesis of both.
