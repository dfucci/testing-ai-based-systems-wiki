Summary: Trajectory analysis studies the sequence of actions an LLM agent takes during task execution to understand behavioral patterns, diagnose failures, and predict outcomes — going beyond binary pass/fail evaluation.

Sources:

  • Kim et al. - 2026 - TRAJEVAL Decomposing Code Agent Trajectories for Fine-Grained Diagnosis.pdf

Last updated: 2026-08-30

Motivation

Outcome-only metrics (Pass@1, Pass@k) tell you what happened but not why. Two agents may both fail, but one failed to find the right file while the other found the right file but edited the wrong function. These require different interventions.

Trajectory analysis converts unstructured execution logs into quantitative, interpretable signals.

Formal Definition

An agent trajectory is T = {(at, ot)}nt=1 where:

  • at = action taken at step t
  • ot = observation received at step t

The agent produces a candidate patch P̂. Trajectory analysis compares T against a reference patch P* to extract stage-specific features.

Approaches to Trajectory Analysis

Stage-wise decomposition (TRAJEVAL)

TRAJEVAL maps trajectory events to three stages (Search → Read → Edit) and computes precision/recall at each stage against a golden context. This enables:

  • Identifying which stage caused failure
  • Quantifying over-exploration vs. under-coverage
  • Predicting task success before completion

Tool use pattern analysis

Analyzing which tools an agent calls, in what order, and with what frequency. Reveals efficiency patterns (e.g., localization percentage — Xdfraction of tool calls that are navigation vs. modification).

Token consumption analysis

Measuring input/output token usage per tool reveals model-specific command strategies. For example, TRAJEVAL found GPT-5-nano generates 26× more bash output tokens than Qwen-30B, reflecting fundamentally different execution strategies. (“GPT-5 nano” and “Qwen-30B” are the paper’s own shorthand in its appendix token table — likely GPT-5-mini/nano and Qwen3-Coder-30B tiers, distinct from the seven main models listed on the TRAJEVAL page.) (source: Kim et al. 2026)

Key Empirical Patterns

From TRAJEVAL’s analysis of 16,758 trajectories:

  • Universal over-exploration: precision 4–8% across all agents; agents examine far more code than needed (source: TRAJEVAL paper)
  • Xg*Recall dominates success prediction*: models that cover required context succeed; models that explore efficiently but miss required context fail
  • Architecture-independent behavior: SWE-Agent, OpenHands, and LiveSWEAgent show consistent behavioral patterns despite different tool primitives, suggesting findings reflect model capability rather than implementation artifacts

Actionability

Trajectory analysis enables real-time intervention. TRAJEVAL demonstrates that injecting confirmatory feedback when agents encounter golden-context files improves Pass@1 by 2.2–4.6pp and reduces cost by 20–31%. This shows trajectory signals are exploitable bottlenecks, not merely correlational patterns.

Contrast with Static Analysis

Static analysis examines code structure before execution. Trajectory analysis examines agent behavior during execution. They are complementary: static analysis can inform runtime enforcement rules; trajectory analysis can diagnose which agent behaviors to target.

Relation to Written Test Suites

Trajectory analysis diagnoses failures after execution, from logs. It is largely orthogonal to what developers write as up-front tests: Tangent’s mining of 2,572 real agent tests found almost no assertions target reasoning/trajectory-level behavior (8.7%, usually presence-only) — see LLM Agent Testing Practice. TRAJEVAL’s over-exploration finding (4-8% precision) is a failure mode current test suites do not check for at all.
