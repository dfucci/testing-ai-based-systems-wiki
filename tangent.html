Summary: Large-scale mining of 2,572 real GitHub tests for LangChain/LangGraph/MCP agents, plus 10 practitioner interviews, producing a 23-pattern testing taxonomy and evidence that agent testing today is shallow, unit-dominated, and rarely covers reasoning or non-functional requirements.

Sources:

  • Pan et al. - 2026 - Tangent An Empirical Study of Testing Practices for LLM-Based Agent Applications.pdf

Last updated: 2026-08-19

Motivation

Almost nothing is empirically known about how developers actually test LLM-based agents (planning, tool use, memory, multi-agent coordination), as opposed to how they’re benchmarked. Prior work focuses on task-completion benchmarks, not test design (levels, objectives, data, assertions). (source: Pan et al. 2026)

Method

Mined 1,190 GitHub Python repos using LangChain, LangGraph, MCP → 209 repos with tests → 240 modules, 2,572 manually labeled test methods (Cohen’s kappa 0.92). Complemented with structured interviews of 10 senior IBM practitioners (5-29 years experience). Released the “Tangent Dataset” (1,723 agents, 4,111 tools, 240 labeled modules) publicly.

Findings

See LLM Agent Testing Practice for the full synthesis against Magalhães et al. 2025’s independent case study. Headline numbers:

  • 61.8% unit-level tests; only 34.6% target interactions; 3.5% multi-tool; 0.1% API-level.
  • Only 7.5% of tests address non-functional requirements (of those: security 49%, performance 33.5%, memory 8.8%, policy 4.6%).
  • 39.9% of tests use dummy placeholder data.
  • Only 8.7% of assertions target reasoning, usually checking presence only, not correctness.
  • Tests are structurally simple: median 14 NCLOC, cyclomatic complexity 1, median 2 assertions.
  • Testing-level distribution correlates with framework abstraction (MCP/FastMCP → unit-heavy; DSPy → integration-heavy).
  • Practitioners report no accepted test-adequacy standard for agents; they rely on post-deployment observability (OpenTelemetry, LangSmith, Langfuse, Arize AI) instead of formal suites.

23-pattern taxonomy

Four categories: test fixtures (mock agent/tool/environment), test data (mocked/real/synthetic/dummy), test objectives (agent/tool, interaction, scenario, end-to-end), assertions (state/output/memory/reasoning/environment). Also proposes an extended testability theory (Freeman’s observability/controllability, extended to agent memory, tool selection, delegation, reasoning traces), and flags a dual-interface mocking challenge: tools expose both a machine API and a natural-language description that shapes LLM reasoning — mocking must simulate both.

Future directions proposed: property-based/metamorphic testing for agents, fault injection/chaos engineering, synthetic persona generation, agent-specific adequacy metrics (tool coverage, persona coverage).
