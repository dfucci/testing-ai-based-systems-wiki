Summary: A multi-agent LLM framework for updating outdated test cases after code changes, using mutation-analysis feedback to strengthen assertions and branch-coverage feedback to guide exploration; outperforms the best baseline by 5.33% line coverage, 19.93% branch coverage, and 16.66% mutation score.

Sources:

Last updated: 2026-10-18

Motivation

When production code changes, existing tests can become outdated (fail to compile, fail at runtime, or silently lose coverage/mutation-kill capability even while still passing). Prior LLM-based test-update approaches (ReAccept, TestUpdater) focus on restoring executability and line coverage, but have three gaps: they generate weak assertions that fail to discriminate correct from buggy behavior (low mutation score), they use coarse line-coverage signals that miss branch logic, and their context retrieval relies on exact-matching which can’t resolve LLM-hallucinated symbols. (source: Tian et al. 2026)

Approach

MuMuTestUp is a four-agent pipeline: an Input Preprocessing agent filters irrelevant context; a Test Update agent performs the actual rewrite; a Coordinator runs the updated test, collects coverage/mutation results, and dispatches to analysis agents; and three analysis agents close the loop — Error Analysis (parses compile/assertion failures and locates the fault), Coverage Analysis (identifies uncovered lines/branches and annotates the focal method), and Mutation Analysis (identifies surviving mutants and instructs the LLM to strengthen assertions to kill them). A Semantic Retrieval agent resolves hallucinated or private symbols via embedding similarity rather than exact matching. Iteration continues until coverage/mutation thresholds are met or a max iteration count is reached. (source: Tian et al. 2026)

The authors also build PRBench, a 571-sample pull-request-level dataset spanning multi-commit test obsolescence across 10 open-source Java projects — broader than prior single-commit datasets.

Findings

With GPT-4.1, MuMuTestUp achieves 88.94% line coverage, 63.36% branch coverage, and 72.39% mutation score, beating the strongest baseline (TestUpdater) by 5.33%, 19.93%, and 16.66% respectively. Ablations show the Mutation Analysis agent is responsible for an 8.99-point mutation-score gain (dropping it barely changes coverage, confirming it targets assertion strength specifically, not exploration); disabling branch-coverage guidance costs 3.55 points of branch coverage; and replacing semantic retrieval with exact-matching costs 5.61 points of compilation pass rate — hallucinated-symbol resolution is a real bottleneck, not a minor detail. An n-gram overlap analysis (0.34 vs. 0.54-0.69 for baselines) suggests the gains are not primarily attributable to training-data memorization. (source: Tian et al. 2026)

Relation to broader wiki

MuMuTestUp is a concrete case of the “LLM proposes, deterministic tool disposes” pattern also seen in ConcoLixir: the LLM drafts an updated test, but only compilation, coverage, and mutation-testing results (all deterministic, executable checks) decide whether the update is accepted. Its use of mutation score as an assertion-strength signal — rather than a standalone testing criterion — is a distinct pattern from Intent-Based Mutation Testing’s use of mutation to generate semantically novel mutants; see Mutation Testing for LLM Systems for the comparison.
