Problem: exhaustive feature-combination coverage doesn’t scale

Coverage-matrix approaches (e.g. ASTRAL) enumerate combinations of discretized input features (content, style, perturbation) and try to cover them systematically. This explodes combinatorially: testing robustness across 8 feature types with ≥5 values each yields over 390,000 combinations — at 5s/test, more than 20 days of continuous execution for one configuration. Search-based testing instead frames generation as an optimization problem, using a fitness function to guide the search toward failure-revealing regions of the input space rather than trying to cover all of it. (source: Sorokin et al. 2026)

Formalization

A search-based testing problem for an LLM application is a tuple \(P = (AUT, D, F, O)\): \(AUT\) is the application under test; \(D \subseteq \mathbb{R}^n\) is the search domain (a feature vector); \(F\) is a vector-valued fitness function scoring a candidate input’s ability to expose faulty behavior; \(O\) is an oracle deciding whether a given input is failure-inducing. Feature values are ordinal (rating scores — mapped to a normalized index) or categorical (venue type — mapped to a raw index), so genetic operators can manipulate them numerically. (source: Sorokin et al. 2026)

STELLAR: feature-encoded genetic optimization for failure detection

STELLAR (the predecessor framework, same author group) runs a standard genetic-algorithm loop over feature vectors:

  • Test representation: sample a feature vector from style/content/perturbation feature sets; encode ordinal features by normalized index, categorical features by raw index.
  • Test generation: decode the vector into a domain-specific prompt template (optionally augmented with RAG-retrieved and few-shot examples), then have a generator LLM turn it into a natural-language test utterance, which is executed against the system under test (SUT).
  • Genetic operators: crossover via Simulated Binary Crossover (ordinal features) and Uniform Crossover (categorical features); mutation via polynomial mutation (ordinal) or uniform mutation (categorical); survival via non-dominated sorting + crowding distance (NSGA-II).
  • Duplicate elimination: candidates whose input embeddings exceed 0.8 cosine similarity are treated as near-duplicates and removed, forcing mutation/crossover to be reapplied.

STELLAR optimizes exclusively for failure detection, so the search concentrates on whichever region of the input space yields the most failures — the resulting test suite ends up exposing only a narrow set of failure modes. (source: Sorokin et al. 2026)

STELLAR-D/DS: diversity as an explicit search objective

STELLAR-D extends the loop with an archive \(A\) of previously-found failing inputs and a repopulation operator, inspired by DeepJanus’s archive + repopulation mechanism for finding failure-region boundaries in deep learning systems:

  • Each candidate’s diversity score is \(Dist(A, x) = \min_{t \in A} dist(t, x)\) — the embedding distance to its nearest archive neighbor. A failing test is only added to the archive if this distance exceeds a threshold (\(th\)), preventing near-duplicate failures from bloating it.
  • Periodically, the repopulation operator replaces the worst-performing (non-failing) individuals in the population. Two sampling strategies are compared:
    • STELLAR-D (uniform): replacement candidates are drawn uniformly at random from the feature space (the original Riccio & Tonella repopulation operator).
    • STELLAR-DS (greedy): for each replacement slot, \(n_{greedy}\) candidates are sampled and the one maximizing distance to the archive is kept — explicitly biasing toward unexplored regions.
  • The archive-distance term is folded into a multi-objective fitness alongside the original quality/failure objectives, still optimized via NSGA-II.

(source: Sorokin et al. 2026)

Effectiveness vs. diversity trade-off (empirical)

Evaluated across 3 case studies (safety, navigation, car control), 5 systems under test, 8 LLMs, 18 configurations, and over 1M executed tests:

  • All guided variants (STELLAR, STELLAR-D, STELLAR-DS) detect substantially more failures than random sampling and combinatorial testing (T-wise, ASTRAL) in nearly all configurations.
  • Non-diversified STELLAR finds the most raw failures — it consistently occupies the high-effectiveness region of the effectiveness/diversity trade-off space.
  • STELLAR-D and STELLAR-DS detect somewhat fewer failures but cover a broader range of failure types (measured via clustering-based coverage and normalized entropy over failure clusters) on all five systems. STELLAR-DS is the best-balanced of the two — in 4 of 5 systems it sits on the Pareto frontier of the effectiveness/diversity trade-off, meaning its extra diversity is not bought at the cost of a uniformly worse detection rate.
  • T-wise and random sampling can reach high diversity too, but only by sacrificing much more failure-detection effectiveness than the diversified STELLAR variants do.

(source: Sorokin et al. 2026)

Relation to diversity-based test selection

This is a distinct mechanism from Test Selection and Prioritization’s Adaptive Random Testing approach: ART-style methods (Yoon et al. 2025) select which already-generated candidate to run next from a fixed pool, maximizing distance to already-selected tests. STELLAR-D instead uses diversity as a generation-time objective inside the genetic search itself — the archive and repopulation operator actively steer what new candidates get synthesized, not just which existing ones get run. The two strategies address different cost bottlenecks: ART helps when the number of LLM queries is the constraint; search-based diversity helps when the goal is broadening the range of failure types a fixed search budget can uncover.
