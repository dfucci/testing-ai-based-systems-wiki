Summary: The golden context is the minimal set of code elements (files and functions) that an agent must examine and modify to correctly resolve a task, derived from the ground-truth reference patch.

Sources: Kim et al. - 2026 - TRAJEVAL Decomposing Code Agent Trajectories for Fine-Grained Diagnosis.pdf

Last updated: 2026-10-18

Definition

Given a ground-truth reference patch P*, the golden context G = (F*, H*) where:

  • F* = set of files modified by P*
  • H* = set of functions modified by P*

The golden context represents the implicitly required context for solving a task: a correct patch tells you exactly which files must be found, which functions must be examined, and which code regions must be modified.

This allows trajectory analysis without manual trajectory annotation — the reference patch itself defines correct behavior. (source: Kim et al. 2026)

Two-Tier Hierarchy

Tier 0 (Core)

Files and functions explicitly modified in P*. Represents the minimal modification footprint.

  • Average: 1.4 files and 2.1 functions per task

Tier 1 (Extended)

Tier 0 augmented with one-hop structural dependencies extracted via static analysis:

  • Imports referenced in modified lines
  • Test files
  • Parent classes via inheritance
  • Average: 4.2 files per task

(source for both tiers: Kim et al. 2026)

How tiers are used

  • Recall metrics computed against Tier 0 (strict measure: did agent find essential code?)
  • Precision metrics benefit from Tier 1 context (exploration of structurally related elements is reasonable, not wasteful)

This hierarchical design distinguishes meaningful exploration from truly redundant reading.

Extraction Methodology

From a unified diff (source: Kim et al. 2026):

  1. Golden Files: files modified, extracted from diff headers (diff --git a/... b/...)
  2. Golden Functions: functions containing modified lines, extracted from hunk headers (@@ ... @@ function_name)
  3. Golden Lines: line ranges modified in each file, extracted from hunk markers

Implications for Agent Evaluation

The golden context exposes a tension in current agents: they achieve high recall (finding required context) but extremely low precision (examining far more than needed). On average agents examine 8–12× more files than in F* and 17–25× more functions than in H*. (source: Kim et al. 2026)

High recall without high precision means agents are correct about what to fix but inefficient about where to look.
