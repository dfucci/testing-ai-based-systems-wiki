Problem: LLM queries are too expensive to test exhaustively

Prompt-testing tools (promptfoo, TruLens, LangSmith, Giskard, DeepEval, ChainForge) let developers run test cases against a prompt template but don’t help decide which cases to run first under a limited budget. (source: Yoon et al. 2025)

Adaptive Random Testing (ART) adapted for prompts

Classical ART generates new random inputs maximizing distance from previously-run tests. Yoon et al. 2025 adapt it to select (not generate) from an existing candidate pool, iteratively picking the input maximizing minimum distance to already-selected tests.

Key novelty — selective reference set: rather than using every previously-run test as the distance reference (as classic ART does), filter to a subset by pass/fail outcome. Rationale: in LLM testing, developers benefit from seeing multiple similar failures (recurring error patterns are diagnostically useful), unlike traditional software ART where similar failures are considered redundant. This inversion of a classical testing assumption is the paper’s central contribution.

Three distance metrics compared: Normalized Compression Distance (NCD), 2-gram cosine distance, Sentence-BERT cosine distance — effectiveness is task-dependent (NCD wins on syntactic tasks, sBERT on semantic tasks).

Results

Tested on 46 prompt templates (BIG-Bench Hard, P3) against GPT-4o/GPT-4o-mini. ART with NCD improved APFD (Average Percentage of Failure Detection) by 7.24% on average over random selection (up to 34.3%), matching or beating Test Set Diameter (TSDm) while running ~25x faster (67s vs. 1,648s for 500/1000-input selection) since ART scales with selection-set size, not pool size squared. The selective reference set variant improved results further across all distance metrics. (source: Yoon et al. 2025)
