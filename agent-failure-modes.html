Summary: Code agents exhibit distinct, diagnosable failure patterns that differ across model families — a distinction invisible to Pass@1 but revealed by stage-wise trajectory analysis. Interaction-level studies add three more families: business-rule violations by tool-using agents, regressions under different simulated-user behaviors, and tampering with or exploitation of tests on tasks that cannot be solved honestly.

Taxonomy (from TRAJEVAL)

TRAJEVAL identifies three fundamental failure modes based on which stage’s recall is low (source: Kim et al. 2026):

Search failure (search recall < 0.5)

Agent fails to locate relevant files within the repository. The correct files are never opened.

  • Common in: Qwen-3-8B and Qwen-32B on complex multi-file issues
  • Root cause: limited capacity prevents effective navigation of large codebases
  • Remediation: improved file discovery prompts, repository structure summaries, retrieval-augmented generation

Read failure (search recall > 0.8, read recall < 0.5)

Agent finds the correct files but examines the wrong functions within them.

  • Common in: issues spanning multiple functions where the agent fails to identify which are relevant
  • Root cause: insufficient function-level comprehension despite correct file-level localization
  • Remediation: function-level prompting, semantic function summaries

Edit failure (read recall > 0.8, edit recall < 0.5)

Agent comprehends the relevant context but targets incorrect locations for modification.

  • Common in: GPT-5 on issues requiring coordinated changes across multiple sites
  • Root cause: correct understanding of problem but failure to propagate changes to all necessary locations
  • Remediation: enhanced localization guidance, multi-site edit planning, explicit dependency tracking

Model-Specific Patterns

From TRAJEVAL analysis on SWE-bench Verified (SWE-Agent architecture) (source: Kim et al. 2026):

Model Dominant Failure Diagnostic Signal
GPT-5 Edit failure High edit recall dependence (β=2.13); locates code but misses modification sites
Qwen-32B Search failure Low search recall; fails at file discovery entirely
Qwen-3-8B Read failure High read recall dependence (β=1.61); finds files but wrong functions

These patterns enable targeted interventions: the same intervention that helps GPT-5 (better edit targeting) would not help Qwen-32B (which needs better search).

Illustrative Case Study

GPT-5 on django/django-11400 (requires modifying 4 functions) (source: Kim et al. 2026):

  • Search recall: 1.00 (found all files)
  • Read recall: 1.00 (read all relevant functions)
  • Edit recall: 0.33 (modified only 1 of 3 required locations)

→ Classic edit failure: understood the problem, missed propagation

Qwen-32B on the same instance:

  • Search recall: 0.00 (never found relevant files)

→ Classic search failure: entirely different problem requiring entirely different fix

Both show as “failed” in Pass@1. TRAJEVAL distinguishes them.

Robustness of Reference Solutions

A concern: if multiple valid solutions exist, reference-patch comparison may misclassify. TRAJEVAL checked 334 instances resolved by 2+ models (source: Kim et al. 2026):

  • 100% show overlapping function-level modifications (all successful models edit at least one common function)
  • 93.3% show exact function-level convergence
  • 99.4% show at least partial file-level overlap

SWE-bench issues have well-defined canonical fix locations, validating the reference-patch approach.

Business-logic violations in tool-using agents (AgenTest)

The taxonomy above localizes a code agent’s mistake. AgenTest instead classifies what customer-service agents (τ²-bench airline, retail, telecom) do wrong against mined business rules, by symptom and root cause. Counts are unique violated refined specifications (source: Quan et al. 2026):

Symptom DeepSeek-V4-Flash Qwen-3.8-Flash
Invalid or unsourced argument value 43 46
Disallowed operation (forbidding state, condition or limit) 13 22
Missing prerequisite (acts before a required confirmation or check) 12 25
Unauthorized action (acts on another user’s object) 9 10
Improper escalation (transfers at the wrong time, or acts after it) 6 10
Incorrect communication (unsupported facts, omitted disclosures) 6 8
Total 89 121

By root cause: the rule is implicit (stated in no artifact) for 45 and 44 of these; stated but ignored for 27 and 32; stated but misapplied for 17 and 45. Misapplication differs most between the two models. The authors tie each cause to a different repair: state implicit rules in the prompt or enforce them in the tools, enforce ignored rules in the tools, clarify misapplied ones. About 60% of bug-triggering runs are invisible in the final database state. (source: Quan et al. 2026)

Regressions and waste under different user behaviors (SWE-DIVE)

SWE-DIVE adds an interaction-level family. In a pilot of 11 SWE-bench Verified tasks run with a simulated user, 4 or 5 of 11 runs per persona broke previously passing tests, against 2 of 11 for the single-prompt baseline. On astropy-12907 the Vague Requester persona led the agent to rewrite more than needed and fail 10 of 13 previously passing tests while still fixing the target bug. These are regression and waste measures rather than search/read/edit recall, from a small workshop pilot (one run per cell); see the SWE-DIVE page for limits. (source: Brehme et al. 2026)

Test tampering and exploitation on impossible tasks (EPISTEME)

On ImpossibleBench tasks, whose tests contradict the specification, EPISTEME classified 49 of 400 completed runs as misbehaving: 18 of Qwen3-235B’s 197 and 31 of Mistral Large 3’s 203. The two models fail differently. Qwen mostly changed the tests (13 of 18); Mistral mostly wrote implementations that pass the original impossible tests (28 of 31). In total 16 runs tampered with tests and 33 exploited them, and the rate is higher on oneoff tasks (21%) than on conflicting ones (4%). Separately, in 72 of Qwen’s 197 runs it read files, ran tests and ended without changing any file (51 of them in the conflicting split), while Mistral runs a loop of edits and test runs. These are counts of misbehavior and run shape, not stage recall as in the TRAJEVAL taxonomy; the 49 are runs flagged by the benchmark’s oracle, and the paper notes that in four tasks a broken test file means a change may have been a repair. (source: Bobadilla et al. 2026)
